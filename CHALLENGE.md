# Challenge PROJECT ACCORD

This file is a navigation surface for external reviewers. It does not replace or modify the
normative challenge contracts under [`challenge/`](challenge/).

## Public research challenge

For a non-sensitive research challenge, start with
[`challenge/README.md`](challenge/README.md).

The canonical public intake remains a GitHub Issue in this repository whose title begins
with:

```text
[ACCORD CHALLENGE]
```

A public challenge may use either the registered-falsification path or, where no published
falsification ID faithfully captures the alleged contradiction, the existing
`NOVEL_FALSIFICATION_HYPOTHESIS` lifecycle path.

Before submitting, review:

- [`CLAIMS.md`](CLAIMS.md) for the normative public claim surface;
- [`challenge/ATTACK-CONTRACT.md`](challenge/ATTACK-CONTRACT.md) for falsification rules;
- [`challenge/LIFECYCLE-CONTRACT.md`](challenge/LIFECYCLE-CONTRACT.md) for intake and receipt state; and
- [`challenge/ADJUDICATION-CONTRACT.md`](challenge/ADJUDICATION-CONTRACT.md) for substantive disposition and claim consequences.

Mechanical acceptance of a submission does not establish that the challenge is true, in
scope, or claim-falsifying.

## Security-sensitive material

Do **not** place confidential vulnerability details in a public challenge issue.

Use the confidential reporting path in [`SECURITY.md`](SECURITY.md), currently
`project_accord@proton.me`.

The distinction remains:

```text
public research challenge != confidential security report
```
